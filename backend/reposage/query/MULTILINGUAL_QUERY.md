# Multilingual query planning

Multilingual planning is disabled by default. To opt in for both API query modes, set the process environment variable `ENABLE_MULTILINGUAL_QUERY_PLANNING=true` before starting the backend. `MULTILINGUAL_REWRITE_TIMEOUT_SECONDS` sets the Ollama HTTP transport timeout (default 8 seconds, permitted range greater than 0 and at most 120). No `.env` changes are required. Programmatic users may pass a `PlannerConfig` to `CodeRAGEngine` or `CodeAgentEngine`; its defaults also bound input characters, output characters, and generated tokens. The transport timeout applies to network operations, not a guaranteed total wall-clock deadline for a streaming response.

`MultilingualQueryPlanner.plan(question, contextual_question=None)` returns an immutable `QueryPlan`: conservative language evidence and reason; original, optional contextual, and optional English rewrite variants with provenance and language; protected spans; and a status. It makes at most one rewrite call. The injected rewriter accepts a masked string and returns one string. The Ollama adapter supplies the existing chat model, a bounded output token count and transport timeout. Errors, malformed or duplicate markers, missing spans, non-English or uncertain output, and model failures fall back without a rewrite. Plans are request-local and contain sensitive user text; do not log or persist them without appropriate access controls.

The rewrite adapter asks Ollama for `think=false` so thinking models can use the bounded token budget for the translated query. The rewrite model is the same `OLLAMA_MODEL` used for answers and Agent calls; there is no separate rewrite-model flag. For isolated validation, use a copy of the Chroma index: live querying on Windows was observed to change the HNSW `length.bin` file even without indexing writes.

The detector uses small lexical indicators and Han script rather than a trained classifier. It abstains when evidence is insufficient. Script alone does not distinguish Chinese from other languages using Han characters. Single ordinary words are not presumed to be identifiers: quote or backtick ambiguous symbols. Recognized code-like identifiers, dotted names, paths, quotes and acronyms are masked and restored exactly; this is a conservative heuristic, not a parser, and cannot guarantee identification of every valid symbol or semantic faithfulness of a translation. Protected text is sent to retrieval, but not to the rewrite model. Contextual variants that lose or duplicate protected spans are dropped.

When enabled, the plan replaces legacy query expansion for that request so its effect can be evaluated independently. The original user question is first; a distinct, span-preserving condensed or Agent search query may be second; at most one English rewrite follows. Standard RAG, streaming RAG, and Agent semantic search use the same retrieval implementation and unchanged RRF. With planning disabled the existing query transformer and its `ENABLE_QUERY_EXPANSION` behavior are unchanged. The internal `_retrieve_and_fuse` optional `plan_observer` receives the plan for controlled diagnostics; it must not be used as a default logger.

Evaluate before enabling broadly: use a versioned and independently judged multilingual set with exact index coverage, compare raw-only, legacy expansion, and multilingual planning at equal retrieval budgets, capture variant-level execution failures and latency, and inspect both per-language and paired per-task results. Validate identifier preservation and translation meaning manually, repeat runs, and report uncertainty. The existing toy benchmark is a smoke fixture, not evidence of multilingual effectiveness.
