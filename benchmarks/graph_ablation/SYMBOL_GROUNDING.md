# Symbol grounding: targeted micrograd smoke

This is a small, unreviewed engineering smoke, not independent research validation. `validation/symbol_grounding_final.json` contains each original question, vector/BM25 candidates, the unchanged RRF seeds, graph additions, exact evidence records, graph data, context checks, errors and latency. It uses the existing Nomic query embedding and a verified isolated copy of `validation/m4a_nomic_snapshot/micrograd` plus the existing v2 sidecar. Query expansion was disabled for this retrieval-only comparison; no answers were generated. The index source hashes remained unchanged. The original index's embedding-model provenance remains undocumented.

Eight identifier-containing variants cover caller and callee requests in English, French, Chinese and mixed language. The exact target `micrograd/engine.py:54–70` was in the RRF top five for four variants and in the final evidence for all eight. The four gains are repeated variants of two information needs, not independent benchmark tasks. The original failing English questions both had the target absent from their RRF seeds and recovered it via exact symbol grounding. This appends graph evidence; it does not rescore or reorder the existing RRF seeds.

For `Who calls Value.backward?`, the graph has no statically resolved incoming edge. It reports `y.backward` and `g.backward` call sites in `test/test_engine.py` as **unresolved targets** with their source locations and citation IDs where the indexed caller is retrieved. Their spelling alone does not establish that they invoke `Value.backward` at runtime. For `What does Value.backward call?`, the graph reports the syntactically resolved call to `Value.backward.build_topo` at `micrograd/engine.py:65`, alongside unresolved `set`, `reversed` and `v._backward` call sites. The distinction is returned in structured `graph` data and shown in the existing evidence panel. The graph gives static references, not verified runtime dispatch.

The identifier-free English question had the exact method in the initial seeds. The Chinese identifier-free question did not recover the exact method in either off/on evidence, though the returned enclosing class contains it. Both report `not_applicable` for symbol lookup and retain the existing multilingual retrieval path. No retrieval execution failures were observed; Chroma telemetry reported errors. The graph off/on comparison is per query with the identical actual seed list. It does not measure answer accuracy.

`validation/symbol_http_smoke.json` records six real Standard RAG streaming requests using `qwen3:1.7b`, multilingual planning enabled, the sidecar, and a separate index copy. EN/FR/ZH/mixed questions and a Chinese identifier-free question all completed. The later `validation/symbol_http_final.json` rechecks the two English cases; both had matched citation IDs, but the caller answer incorrectly attributed a `g.backward()` call to `test_sanity_check`, and the callee answer incorrectly said `build_topo` performs gradient computation. A valid ID does not verify a claim. In the broader smoke the mixed answer also incorrectly called the backward traversal a forward pass, and the French answer cited the ReLU chunk for a `backward` claim. These are observations requiring review, not validated labels.

`validation/symbol_agent_http_verified.json` records a natural Agent request after the HTTP response-model fix. The model executed no tool, correctly returned `rag_fallback_no_tools`, and the HTTP response retained the matched root, one static relationship and three unresolved call sites. Its answer was truncated and inaccurate about traversal. A deterministic Agent test separately exercises a real semantic-tool invocation and verifies original-question preservation and citation remapping; it does not prove autonomous tool use in the live run.

Exact lookup accepts explicit dotted names and backticked or call-syntax single names; bare ordinary words are not assumed to be code. It uses exact qualified names and optional exact repository-relative file context. Duplicate or unknown candidates abstain from graph grounding, while semantic retrieval still runs. Python identifiers outside the ASCII syntax recognized by this narrow lookup, relative-import resolution, dynamic dispatch and questions with multiple explicit symbols remain limitations. A matching graph node must map to an indexed source chunk; a short symbol can map to a verified enclosing class, whose actual range remains the evidence range. Existing indexes need a separately built v2 sidecar, and graph additions—not total RRF context—are bounded.

The current application can demonstrate traceable retrieval and explicitly uncertain graph data. It is not yet ready to be presented as a reliably factual multilingual code assistant: the local generation failures, lack of independently reviewed acceptance judgments, limited symbol parser, and missing exact Chinese identifier-free retrieval remain material gaps.
