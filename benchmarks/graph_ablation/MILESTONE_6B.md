# Qualified graph integration: micrograd smoke

This is an automatically source-derived smoke, not independently human-validated performance. The original Milestone 6A six-task dataset is unchanged; the 24 questions are four correlated multilingual variants per task, not independent tasks. Queries explicitly name files and symbols. The existing Nomic index snapshot was copied and verified before querying; its source hashes remained unchanged. Its original indexing embedding model is not documented. The real output is in `validation/m6b_graph_complete.json` with task-level summary in `validation/m6b_graph_complete_summary.json`. Each row contains raw vector/BM25 candidates, actual RRF seeds, qualified seed nodes, one-hop graph edges, unresolved calls, graph additions, evidence records, and context-inclusion checks.

The v2 sidecar was built from the source checkout and the existing trusted BM25 documents without opening or changing the original index. It contains 40 nodes, 15 resolved static call-site edges and 55 unresolved call sites; 14 nodes match exact indexed chunks and 26 map to verified enclosing class chunks. All 15 resolved edges match the independent Milestone 6A AST reference at the same source/target/call-site location. No conflicting edge was identified by that static check; it does not verify runtime dispatch or prove the absence of errors. The graph omits unresolved edges and never treats class containment as a call. Same-named symbols have distinct identities.

Eligible task macro recall was 0.875 off and 1.000 on, calculated by averaging the four variants inside each task, then averaging the five eligible tasks. Across all six tasks eight correlated query variants gained a relevant target: two for the local call, three for the covered cross-file call, and three for the cross-file task whose short caller is not a standalone indexed chunk. Those gains are not eight independent tasks or proof of broader retrieval performance. The short method maps to its indexed enclosing class where its text is available, but this does not turn the method into an exact standalone chunk.

For example, the English local-call query's RRF seeds included `backward` but not `build_topo`; the qualified edge added `micrograd/engine.py:59–64`. This was the supported edge missed by the legacy first-three cutoff. In the French cross-file query, `test_sanity_check` was a seed and the graph added the exact `Value` class chunk from `micrograd/engine.py:2–94`. All new graph evidence IDs appeared with their paths and ranges in the formatted generation contexts. A deterministic test also captures the messages in the actual RAG query method and verifies the same mapping. This is context inclusion, not proof that the model uses or correctly explains it.

All 24 retrieval queries completed without observed failures. The graph added 51 source documents (mean 2.125/query) with zero duplicate seed identities. Mean added formatted-context size was 2,894 characters; the graph stage averaged 0.485 ms, excluding formatting, retrieval and model generation. The bounded graph additions use at most six chunks and 8,000 source characters; RRF seed context itself is not bounded by this feature. On four reruns of the indexed cross-file task with identical seeds and additions, Qwen `prompt_eval_count` increased by 1,043, 886, 718 and 886 tokens (mean 883.25). These one-token model probes include the complete prompt and are not end-to-end latency measurements. See `validation/m6b_graph_complete_tokens.json`. Chroma emitted telemetry errors, although retrieval completed.

The former legacy false class-level `Value → build_topo` relationship is absent from the v2 graph. However, static `self` references can still dispatch dynamically, module rebinding outside simple module assignments is not fully analyzed, and relative imports, inheritance and non-Python languages are not resolved. Unknown calls remain explicitly recorded, rather than guessed. Existing indexes without a supplied sidecar still use the old graph for backward compatibility and retain its documented limitations. Sidecars created from existing indexes require the operator to use the corresponding source checkout: chunk-text matching cannot independently establish that imports and the entire checkout match the historical index revision.

Two additional real queries, `Who calls Value.backward?` and `What does Value.backward call?`, selected caller and callee direction respectively, but neither put the requested method in its top-five RRF seeds. The qualified-symbol guard therefore added no graph evidence for either query instead of following unrelated seeds. This is a retrieval limitation, not a successful caller/callee answer; see `validation/m6b_direction_final.json`. All 24 benchmark questions used the ambiguous/both-directions route, so this guard did not affect their recorded ablation.

The compatibility and migration instructions are in `backend/reposage/query/SOURCE_GRAPH.md`. No existing `graph.pkl`, Chroma index, source checkout or historical report was overwritten.
