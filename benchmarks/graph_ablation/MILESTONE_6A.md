# Current graph execution and real-index ablation

This report is an automated engineering smoke, not independently human-validated ground truth. It evaluates 5 AST-derived tasks and 20 language variants on the existing micrograd index copied to a verified isolated snapshot. These are four variants per task, not 20 independent tasks. Exact data and full query traces are in `validation/m6a_benchmark_v2.json`, `validation/m6a_graph_ablation.json` and `validation/m6a_graph_summary.json`. Source revision is `7bc720e951fe422b8f8814aa5aa1b64121d26b4c`; source hashes are in the dataset. The source snapshot hash remained unchanged. Nomic query embeddings were used; the source index did not record the original indexing embedding model. `qwen3:1.7b` token probes used 1 generated token and the actual graph-off/on prompt templates.

These generated questions explicitly name the target symbols and files, including both endpoints of relationship tasks. This makes the evidence needs mechanically checkable but makes retrieval easier than identifier-free user questions. The fixed multilingual templates were authored by Codex; their linguistic naturalness has not been independently verified, and no free-form runtime LLM paraphrasing was used.

## Current code execution map

1. `backend/reposage/chunkers/python_chunker.py:83` walks Python definitions; definitions under five lines are skipped. `:114–119` recursively walks each selected definition, reduces calls to a bare `Name.id` or `Attribute.attr`, and includes calls inside nested definitions and class methods in their parent chunk. It does not resolve imports or receiver types. JavaScript uses separate heuristics.
2. `backend/reposage/ingestion/repo_indexer.py:196–207` builds chunk documents, including names, relative paths, lines and calls. `:279–291` uses bare names as `networkx.DiGraph` nodes, attaches a single file attribute, adds directed caller-to-callee edges, and pickles the graph. Same names merge, subsequent node attributes overwrite earlier values, and undefined or external callees can appear as implicit nodes without source documents. The saved `calls` order originates in a set and may differ between rebuilds.
3. `backend/reposage/query/rag_engine.py:145–165` rebuilds BM25 from persisted documents and loads `graph.pkl`. `_retrieve_and_fuse` at `:247` searches vector and BM25 and runs RRF at `:327`. At `:333`, one dictionary entry per bare name selects the last matching BM25 document. Each RRF seed is matched by its unqualified metadata name. At `:341–356`, predecessors (callers) precede successors (callees), only the first three combined neighbor entries are considered, resolvable documents are copied and appended, and unresolved neighbors are omitted.
4. At `:171–201`, `_format_context` uses stable evidence identities and source IDs, skips invalid or duplicate identities, and emits source code with file and line headers. `query` and `aquery_stream` (`:364`, `:426`) pass that context to the LLM prompt. The raw graph additions can include a seed again when vector and BM25 `Document` metadata differ, but evidence formatting removes the duplicate stable identity. All 42 per-query new evidence occurrences in this smoke appeared in the constructed on-context; this proves prompt inclusion, not model attention or factual use.
5. The repository call graph is not the LangGraph workflow in `backend/reposage/query/agent_engine.py:83`: the latter orchestrates Agent model/tool turns. Agent `semantic_search` invokes the shared RAG path and exposes an intermediate generated answer and references to the Agent, rather than directly exposing every raw context chunk.

## Graph-on/off results

Each query executes retrieval once. Off is the observed pre-graph RRF seed list and on is that identical list plus actual graph additions; no separate retrieval call can change the comparison. Five vector and five BM25 candidates and five RRF seeds were requested. Exact target coverage requires matching file, bare symbol name and full source range; all targets must exist in both index components for a task to enter the conditional metrics. Graph expansion may extend the context beyond five.

| Task | Exact target index coverage | Graph off: mean target recall across four variants | Graph on | Both targets present, off → on |
|---|---|---:|---:|---:|
| Exact `Value.__add__` definition | 1/1 | 1.00 | 1.00 | n/a |
| Same-named `Value.__init__` definition | 1/1 | 1.00 | 1.00 | n/a |
| `Value.backward` → nested `build_topo` | 2/2 | 0.75 | 0.75 | 0.50 → 0.50 |
| `Neuron.__init__` → imported `Value` | 1/2 | ineligible | ineligible | unindexable exact caller |
| Unresolved `set` call site | 1/1 | 1.00 | 1.00 | n/a |

Macro exact recall across the four eligible **tasks**, first averaging each task's four variants, was 0.9375 off and 0.9375 on. This is not evidence that graph expansion is generally useless: the selected cross-file task is excluded because `Neuron.__init__` is four lines and the existing chunker does not index it as a separate chunk. For the French and mixed variants of that task, graph expansion added the relevant `Value` class where it was absent from the RRF seeds, but could not add the unindexed caller. Those are two correlated query observations on one task, not two independent successes.

The English local-call query retrieved `backward` as a seed. Its first three graph neighbors were two test callers and unresolved `append`; the statically supported `backward → build_topo` edge appeared later and was not traversed. Consequently `build_topo` was missing from both off and on exact evidence. In the French exact-definition query, `build_topo` was a seed, and the persisted edge `Value → build_topo` caused the enclosing `Value` class to be added as a caller. This edge comes from walking nested class/method bodies and does not establish a direct class-level call: the actual direct lexical call is inside `Value.backward`. It illustrates a misleading graph relationship, not proof that the added source is always irrelevant.

The raw graph stage appended 53 document instances across 20 variants; 11 were duplicates of an existing seed by stable identity, leaving 42 new evidence IDs. The 11 duplicates occurred in 8 query variants and were filtered from formatted context. For each seed we also inspected the first three neighbor entries: across repeated variants there were 28 statically supported references, 99 not established by the conservative oracle, and 125 with no matching indexed chunk. These are neighbor observations, not independent edges, and `not_established` is not an assertion that a relationship is false. No conflicting-resolved-target observation was found in this small run; a deterministic synthetic test demonstrates that a same-name collision can nevertheless select the wrong file.

Every query completed without reported retrieval errors. All 20 on/off prompt-token probes succeeded: graph additions increased the complete prompt by a mean of 670.35 Qwen prompt tokens, range 139–1,012. Mean observed graph traversal between the RRF and graph observer callbacks was 0.129 ms, excluding retrieval, formatting and model prompt processing. Retrieval and probe timings were collected sequentially with model switching and are not a controlled end-to-end latency comparison. The new graph context increases model processing even when the traversal itself is fast.

### Additional indexed cross-file task

The reproducible generator now also selects a cross-file call whose two source definitions are at least five lines long. The additional `call-5` task asks for `test/test_engine.py:test_sanity_check → micrograd/engine.py:Value`; the AST independently identifies the imported `Value` call. Both exact target chunks are present in both index components. Its four variants were run in a separate verified snapshot and reported in `validation/m6a_crossfile_ablation.json` and `validation/m6a_crossfile_summary.json`; `validation/m6a_benchmark_v3.json` contains all six tasks. The first five task facts and questions are unchanged.

Across its four correlated variants, mean exact target recall was 0.625 off and 1.000 on, and both-target coverage rose from 0.25 to 1.00. In the French, Chinese and mixed variants the graph added the previously missing `Value` chunk; the observed `test_sanity_check → Value` edge is supported by the explicit import and source call. The English seeds already contained both targets. All added evidence reached the constructed context. The four prompts added an average 956.25 tokens (range 801–1,008) and mean graph-stage time was 0.171 ms. The source snapshot again remained unchanged.

Across both runs, there are six tasks, five eligible tasks and 24 correlated query variants. Averaging language variants within each eligible task and then tasks equally gives exact target recall of 0.875 off and 0.950 on. Five variant observations gained a relevant target, across two tasks; one of those tasks remains ineligible for complete exact coverage. The 24 prompt probes averaged 718 extra prompt tokens. This is a useful concrete graph contribution on this small automatically derived fixture, not a general performance estimate.

## Next step

The source-only `experimental-qualified-static-graph-v1` artifact (`validation/m6a_qualified_graph.json`) demonstrates file + lexical qualification + range identity, statically resolvable links, and explicit unresolved calls. It is disabled in production and not written over persisted data. Its 40 nodes, 15 resolved syntactic references and 55 unresolved calls are a conservative subset, not a verified complete runtime call graph. Extend it with import/package resolution and source-chunk coverage metadata; compare its evidence additions against the legacy graph using the exact same retrieval seeds and task-level evaluation on multiple repositories before considering a versioned index migration. Test collisions, nested scopes, dynamic dispatch and unindexable chunks; do not treat resolved syntax alone as runtime proof.
