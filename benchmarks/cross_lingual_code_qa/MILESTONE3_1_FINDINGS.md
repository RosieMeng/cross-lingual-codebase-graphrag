# Milestone 3.1: saved-trace diagnosis

Scope: `validation/milestone3_live_final.json`, a single 15-query micrograd smoke with generated, unverified candidate judgments. Full channel and stage rankings for every query and arm are in `validation/milestone3_1_error_analysis.md`. No new retrieval was run for this analysis. The first candidate rank means the first match to either `Value.backward` **or** the encompassing `Value` class for the backward task; neither alternative has been independently judged. The two are not interchangeable by default.

## Observed in the saved traces

- Translation-only and retriever-specific have identical vector queries and vector ranked metadata for all 15 queries. Each arm made one vector and one BM25 call per query, with candidate limit 5. Their BM25 query and ranking records differ in nine queries.
- On six identifier-free queries (`free-fr`, `free-zh`, `free-en-fr`, `free-en-zh`, `free-fr-zh`, `free-en-fr-zh`), translation-only puts the first candidate at RRF rank 1 and retriever-specific at rank 3. That accounts exactly for the aggregate MRR@5 difference: `6 * (1 - 1/3) / 15 = 0.2667`. These are different language forms of one information need, not six independent tasks.
- For `free-fr`, both vector lists start with `Value` then `backward`. Translated BM25 has `backward` at rank 2 and `Value` at rank 4, while raw French BM25 contains neither candidate in its top five. Translation-only RRF starts `backward`, `Value`; retriever-specific starts `test_more_ops`, `Layer`, `Value`, `README`, `backward`. Shared vector/BM25 noncandidate chunks receive two RRF contributions while the vector-only candidates receive one. This follows the existing fusion implementation; it does not establish whether the judgments are correct.
- For `free-zh`, translated BM25 has `backward` at rank 2 and `Value` at rank 3; raw Chinese BM25 has neither candidate in its first five. Both arms' vector rankings are identical, and translation-only ranks `Value` first versus third for retriever-specific. In this trace raw Chinese contains no whitespace, so the installed BM25 preprocessing makes it one query token. The report does not record BM25 term scores or corpus-token matches; it does not prove why that channel produced its ordering.
- Identifier-present mixed queries `id-en-fr` and `id-en-zh` also show different BM25 candidate rankings, but both arms still rank a candidate first after RRF. A BM25 difference alone did not always change the first candidate rank. All six measured rank gaps are identifier-free; the sample is too small and confounded by task identity to infer a population-level identifier effect.
- Three identifier-present variants fell back in both arms: `id-fr` and `id-fr-zh` (`rewrite_not_english`), and `id-zh` (`rewrite_invalid`). Their corresponding RRF rankings match across the two arms. The traces do not preserve rejected model output, so they cannot establish precisely what the model generated in each failure. Those fallbacks do not explain the six observed rank gaps.
- Milestone 2 can issue two searches per retriever after a rewrite; its original-first flattening and content deduplication precede the unchanged RRF. It is an expanded-budget arm, and its results cannot isolate a translation effect. Graph results are appended after the five RRF entries. The reported metrics use only pre-graph RRF; graph additions cannot explain the reported MRR difference.

## Hypotheses and unresolved questions

The raw lexical channel's whitespace tokenization and English-heavy corpus are plausible contributors to its different rankings, especially for unsegmented Chinese. The saved report lacks term-level scores, exact document tokens, and a controlled tokenization ablation, so it does not prove tokenization is the cause. RRF's equal channel contributions then explain how the recorded channel rankings combine, conditional on those rankings. The logs do not prove general effectiveness, semantic preservation of translations, or that the encompassing class should count as an answer.

## Timing scope

The evaluator starts each per-query timer before `plan_for` and stops after retrieval, graph enrichment, scoring and per-query trace construction. It includes LLM rewrite generation, model wait, embedding/search and tracing overhead, but excludes initialization, snapshot creation, dataset loading, report serialization, HTTP API and answer generation. `llm_call_events` time the rewrite callback, including model response generation. Vector and BM25 calls can overlap, so their durations should not be added to calculate wall time. Arm order is fixed (raw, translation-only, expanded, retriever-specific); model caching, warm-up and repeated calls confound the mean latency comparison. The first raw query was especially slow. These timings are diagnostic, not a controlled latency benchmark.

## Next experiments in priority order

1. Independently review the task, its translations and each candidate evidence span, especially whether the `Value` class is an answer or only context. Separately score exact `backward`, reviewed alternatives and index coverage.
2. Freeze one reviewed translation per query, reuse the same vector query and compare raw versus translated BM25 with exactly one call per channel, equal candidate limits and fixed RRF. Capture term scores, query and indexed tokens, stable chunk identities, ties and per-channel failures. Randomize arm order and repeat runs on a verified snapshot.
3. Hold BM25 fixed and vary only the vector input; inspect graph enrichment separately. This distinguishes vector rewriting from lexical formulation and downstream graph effects.
4. Repeat on independently authored natural mixed-language queries and repository-disjoint held-out repositories; use paired task-level intervals and report cost, fallbacks and subgroup denominators. Treat the present 14 backward variants as one task cluster.
5. Only as a separately proposed index experiment, compare compatible query/index tokenization strategies and identifier-aware lexical fields against a frozen baseline. Do not change the production BM25 tokenizer or rebuild an index during this diagnostic milestone.
